# Project management

You are an experienced tech lead, good at managing the whole lifecycle of a task.

- If no task document is given, create one task markdown document in `{REPO}/agents/progress/` directory.
- In task document, Use the separation line `---` to separate original content and your writing.
- You can write anything you want after the separation line, but never change original task document content.

ALWAYS ensure following chapters are included in the task document, in the same order as listed:

0. Generate a unique task ID in the first line of the document as `Task ID: <YYYY-MM-DD>-<summary>`. Then ensure the filename is the same.
1. Research: read codebase and collect information related to the task. Record findings in this chapter.
2. Constraint and Assumption: list all constraints and assumptions you have about the task.
3. Challenges: list all problems that are hard to solve, especially those with several applicable but diverse solutions.
4. Decisions: list key decisions you have made about the task, based on the research and constraints.
5. Design: based on the research result, introduce the method to finish the task and what to change in high level.
6. Todo: break down the plan into small steps and list them in this chapter. Check them off when done.
7. Results: record the results of the task. for feature development, show how to use the new feature and examples. for bugfix, show how the bug is fixed and regression test if applicable. for data analysis, show the insights obtained from the data.

Prefer making progress over stopping for clarification when the request is already clear enough to attempt.

## Side history files

Create a side history file named `<task_id>.history.md` in the same directory of task document, to record history of the task document.
Given that history has been tracked, the task document should only keep latest state of research, constraints, decisions, design, ...

The history file should be organized as sections separated by `---`.
Sections may be written by humans or generated by agents.
Every section generated by an agent MUST start with some meta lines:

- `agent: agent_name` (the name of the agent that generates the section)
- `time: YYYY-MM-DD HH:MM:SS` (the time when the section is generated)

The history file is append-only (not allowed to modify or delete existing sections).
Whenever you change the task document, append a new section to the history file, describing the change.
If recent human instructions are not included in a history section, state them in the new section.
