## Research

| Term | Meaning | Source |

- `README.md` documents the current setup path: install/sync with `uv sync`, run the demo with `uv run xhtang-harness "Show a usable agent harness demo"`, and run checks with pytest, ruff, and mypy. [source: `README.md`]
- `src/xhtang_harness/cli.py` currently supports only the optional positional `goal` and `--version`; it renders `xhtang-harness demo`, version, goal, and `status: ready`. [source: `src/xhtang_harness/cli.py`]

- `agents/2026-05-30-mvp-implementation.md` recommends worktree-local `.xhtang-harness/` state by default and explicit shared state only through `--state-path` or `XHTANG_HARNESS_STATE_PATH`. [source: `agents/2026-05-30-mvp-implementation.md`]

## Constraint and Assumption

- This task is documentation-only. [source: user request]
- The usage document must be useful to an MVP application user while staying honest that the current checkout still implements only the demo CLI. [source: `src/xhtang_harness/cli.py`, `doc/mvp.md`]
- The usage document should include minimal use, settings/customization, FAQ, and troubleshooting. [source: user request]
- Documented target-MVP options should be clearly marked as planned when they are not implemented in `src/xhtang_harness/cli.py` yet. [source: `src/xhtang_harness/cli.py`, `doc/external-interfaces.md`]
- Facts and assumptions in markdown should include source labels. [source: `AGENTS.md`]

## Challenges

- A user-facing usage file should not imply that planned MVP features are already runnable. [source: `src/xhtang_harness/cli.py`, `doc/mvp.md`]
- The settings list is defined in design docs but not implemented in the current parser. [source: `doc/external-interfaces.md`, `src/xhtang_harness/cli.py`]
- Troubleshooting needs to cover both current local setup problems and future DeepSeek/provider/runtime problems. [source: `README.md`, `.agents/skills/deepseek-api/SKILL.md`]

## Decisions

- Create `USAGE.md` at the repository root for application users. [source: user request]
- Include a short status note that separates current demo behavior from target MVP behavior. [source: `src/xhtang_harness/cli.py`, `doc/mvp.md`]
- Use tables for settings and troubleshooting so source labels can be attached without making the guide hard to scan. [source: `doc/external-interfaces.md`, `AGENTS.md`]
- Include parallel-worktree guidance because the previous MVP implementation request explicitly asked for simultaneous multi-worktree separation. [source: `agents/2026-05-30-mvp-implementation.md`]
